## 2024-03-24 - DOM Caching in high-frequency game loops
**Learning:** In vanilla JavaScript clicker games, repeatedly querying the DOM with `document.getElementById` or `document.querySelector` inside rapid event listeners (like user clicks) and fast intervals (like 500ms damage loops) causes unnecessary layout thrashing and CPU overhead. Additionally, when caching audio elements that trigger on rapid events, simply calling `.play()` on the cached element will not restart the sound if it's already playing.
**Action:** Always cache static DOM elements globally or in closure scope instead of querying them repeatedly. When caching audio elements for rapid playback, reset `element.currentTime = 0` before calling `.play()` to ensure the sound effect triggers correctly on overlapping events.
